# HandMark · 隔空绘画（macOS 原生）

用 Mac 内置摄像头识别手部，拇指与食指捏合即可在屏幕内容（PPT 等）上隔空画荧光笔轨迹。
纯 Swift + AppKit + AVFoundation + Vision，无浏览器、无 Electron、无后端、无联网。

## 一、功能

| 功能 | 说明 |
| --- | --- |
| 透明画板 | 全屏透明覆盖窗口，底层 PPT 清晰可见；`ignoresMouseEvents=true`，鼠标/键盘完全穿透到底层应用 |
| 隔空绘画 | Vision 追踪食指指尖；**拇指+食指捏合开始绘画，松开停止**；荧光笔轨迹（圆头 + 发光）直接叠加在屏幕内容上 |
| **指尖激光光点** | 识别到手即在屏幕显示红色激光式光点（大光晕 + 红核 + 白心 + 轻微呼吸），**常驻跟随食指指尖**，与落笔坐标同源；捏合绘画时光晕放大 1.25 倍作为落笔反馈；手离开画面即隐藏，不留残影（V2.1 起不再需要激光手势触发） |
| **手势清屏（六→握拳）** | 先比「六」手势（拇指+小指伸直）稳定 180ms 就绪 → 1 秒内握拳稳定 180ms → 自动清空全部笔迹；清屏优先于绘画，冷却 800ms 防连触 |
| 摄像头预览小窗 | 屏幕左上角 300px 小窗：实时画面 + **五指关键点骨架**（拇指/食指/中指/无名指/小指，指尖带「拇食中无小」标签）+ 状态条；**复用同一路摄像头**，不另开采集 |
| 状态显示 | 等待摄像头 / 摄像头已开启·未识别到手 / 已识别到手 / 捏合候选（带 xx/150ms 计时）/ 正在绘画；权限或设备异常时明确显示原因；第二行实时显示 `d=0.312 (45px) 掌宽=171px 置信度=0.89 状态=候选`，低置信度点画成空心灰虚线点 |
| 隐藏/显示预览 | 面板「隐藏预览」按钮；隐藏后后台手势识别与屏幕绘画照常运行，且不再生成预览图像以省开销 |
| 退出 | 菜单栏 ✋ → 「退出 HandMark」，或关闭预览窗口 |
| **五指旋钮（V3.0）** | 五指张开稳定 300ms 进入旋钮模式（期间禁止落笔）；**顺时针**累计 30° 循环切换笔刷粗细（粗 12px → 中 6px → 细 2px → 粗），**逆时针**累计 30° 循环切换颜色（黄 → 蓝 → 黑 → 绿 → 白 → 黄）；**一次激活只切一档**——切完后回程旋转不再触发，必须收手、重新五指张开才能再切（改完粗细不会因回手被改颜色，反之亦然）；屏幕顶部短暂显示「笔刷：粗」或「颜色：蓝色 + 色块」，1.4 秒后自动消失，不阻挡 PPT |
| **拇指音量（V3.0）** | 拇指朝上/朝下且其余四指弯曲，稳定 300ms 后调节**系统输出音量**一档（±10%），冷却 500ms；必须回到非目标手势才能调下一档；屏幕顶部短暂显示「音量 ↑ 38%」，实际值以 Core Audio 回读为准 |
| **笔刷状态可见** | 预览小窗右上角常驻显示当前笔刷（粗细 + 颜色色块，白色带深色轮廓），本次切换只影响后续新笔画，历史笔迹颜色/粗细不变 |
| **固定活动区域映射（V4.0）** | 校准一次「舒适活动范围」，之后在该范围内移动即可覆盖**整块屏幕**，不必把手伸到摄像头画面边缘。未校准时自动沿用「整幅画面→全屏」的 Legacy 映射 |
| **1€ Filter 指针滤波（V4.0）** | 速度自适应低通：手静止时强滤波压抖，手快速移动时自动减弱滤波保持跟手。原固定 EMA 保留为 Legacy 模式可随时切换对比 |

窗口层级（实测）：控制面板 1002 > 摄像头预览 1001 > 全屏透明画板 1000，因此预览和面板不会被笔迹盖住，也不会被 PPT 全屏窗口遮住。

## 二、启动方式

```bash
cd /Users/wangguangzheng/Desktop/HandMark
./build.sh            # 编译 release、打包 HandMark.app、自动生成并嵌入 AppIcon.icns
open HandMark.app     # 启动（首次会弹摄像头授权框，点「好」）
```

图标源图放在 `assets/icon.png`（当前为 handmark 蓝底手势图），每次 `./build.sh` 自动裁剪成方形并生成 16~1024 全尺寸 `AppIcon.icns`；图标在 Finder / 启动台可见。因 `LSUIElement=true`（不抢焦点、不出现在 Dock），Dock 里不显示图标，属预期行为。

也可直接跑二进制（权限归属于启动它的终端/IDE）：

```bash
swift build -c release && ./.build/release/HandMark
```

> 摄像头权限：首次启动弹系统授权框。若误点拒绝，到 系统设置 > 隐私与安全性 > 摄像头 中勾选 HandMark（或启动它的终端），重启即可；程序也会在小窗里明确提示原因。
> 运行时日志：`~/Library/Logs/HandMark.log`（每 3 秒一条心跳：已处理帧数、是否识别到手、捏合距离、指尖屏幕坐标、预览帧数）。

## 三、使用步骤

1. 打开 PPT（普通窗口或全屏均可）。
2. 启动 HandMark，左上角出现摄像头小窗，右上角出现控制面板。
3. 把手举到摄像头前 → 状态变为「已识别到手」，屏幕上出现**红色激光式光点**（跟随食指指尖，就是落笔位置）。
4. **拇指与食指捏合** → 状态变「正在绘画」，光点光晕放大，移动手指即可在 PPT 上留下荧光笔轨迹。
5. 松开手指 → 停止绘画；点「清除笔迹」清空；点「隐藏预览」只收起小窗（绘画功能不受影响）；菜单栏 ✋ → 「退出 HandMark」结束。
6. **手势清屏**：先比「六」（🤙，拇指和小指伸直）保持约 0.2 秒 → 再握拳保持约 0.2 秒 → 笔迹自动清空。日志会出现 `🧹 六→握拳清屏，清空笔迹`。
7. **五指旋钮**：五指张开保持约 0.3 秒 → 日志/预览出现「旋钮模式」→ **顺时针**转手掌切粗细、**逆时针**转手掌切颜色（转过约 30° 切一档）。**一次张开只切一档**：切完把手转回原位不会再触发；要再切就收手（捏合或放下手）退出，再重新五指张开进入。这样改完粗细不会因回手被改成颜色，改完颜色也不会被改成粗细。
8. **音量**：拇指朝上（其余四指弯曲）保持约 0.3 秒 → 音量 +10%；拇指朝下 → −10%。保持不动不会连续调节，必须先松开再做。
9. **校准活动区域**（可选，但推荐）：菜单栏 ✋ → 「校准活动区域（4 步）」→ 屏幕顶部出现提示，按 ①左上 ②右上 ③左下 ④右下 的顺序把手移到**你觉得舒服的极限位置**并保持不动（每步静置 1.2 秒 + 采集 1.0 秒）。四步完成后提示「校准完成：已启用活动区域映射」，此后的移动范围即放大到整块屏幕。想恢复旧行为：菜单栏 ✋ → 「重置为全画面映射」。校准结果存 `~/Library/Application Support/HandMark/roi.json`。

> 校准的是**手部舒适范围**，不是屏幕四角。要求指针指到屏幕四角，就等于要求手伸到画面边缘——那正是本功能要消除的问题。

### 清屏手势的判据与调参

握拳判定不使用「指尖绝对位置」，而用**掌部骨架**（腕关节 + 各指 MCP）做参照，因为握拳时蜷曲手指的指尖/DIP 会被遮挡、置信度天然极低。核心阈值在 `Sources/HandMarkCore/PoseClassifier.swift`：

```swift
CURL_MAX      = 0.62   // 单指弯曲度 dist(指尖,指根)/掌长，低于此值判为蜷曲
STRAIGHT_MIN  = 0.70   // 高于此值判为伸直（与 CURL_MAX 形成滞回）
FIST_CURL_STRAIGHTEN_MAX = 1.35  // 辅助判据：指尖↔腕 / 指根↔腕 不高于此值
                                 // （真握拳实测 1.15~1.35；捏合绘画的半握手型 1.41~1.64 仍被排除）
FIST_SPREAD_MAX = 1.3  // 四根长指指尖最大跨度 / 掌长，低于此值判为收拢（**不含拇指**）
CLEAR_MIN_CONFIDENCE = 0.15  // 掌部骨架置信度门限（不是指尖置信度）
```

> 握拳「识别不到」的两个历史坑（已修）：① 收拢度把**拇指指尖**算进最大跨度，握拳时拇指绕在四指外侧，把收拢度顶到 1.9~3.0 而永远判不出「收拢」；② 掌部骨架置信度取 6 个关节的**最低值**，thumbCMC / littleMCP 任意一个被遮挡就整帧判为不可靠。现在收拢度只用四根长指，置信度丢弃最差的一个关节取次低值。

清屏时序参数在 `ClearConfig`（`Sources/HandMarkCore/Gesture.swift`）：

```swift
sixConfirmMs        = 180   // 「六」稳定多久才就绪
sixToFistTimeoutMs  = 2000  // 就绪后必须在多久内握成拳（原为 1000，实测太仓促）
fistConfirmMs       = 180   // 握拳稳定多久才执行清屏
fistLossToleranceMs = 300   // 握拳确认期允许掉帧的容忍窗（收指瞬间 Vision 常抖 1~2 帧）
cooldownMs          = 800   // 清屏后冷却，且必须先松开握拳才能再清一次
```

清屏流程会在日志里逐步打点，卡在哪一步一眼可见：

```
🤙 清屏：检测到「六」，请握拳保持 180ms 清空笔迹（2000ms 内有效）
✊ 清屏：握拳识别中，保持 180ms 即清空
🧹 六→握拳清屏，清空笔迹
⌛ 清屏取消：「六」就绪后 2000ms 内没握成拳（握拳[弯曲度 … → 未命中]）
```

调参入口在心跳日志里：`握拳[弯曲度 食x 中x 无x 小x | 可见n 蜷曲n 伸直n | 收拢=x 掌置信=x | 蜷曲√/× 收拢√/× 可靠√/× → 命中/未命中]`，哪一项打 × 就调哪一项。

捏合距离 = 拇指尖↔食指尖像素距离 ÷ **手掌尺度**（掌宽 = 食指掌指关节↔小指掌指关节，与「掌长×0.85」取较大者，带突变保护与指数平滑），因此不受手离摄像头远近、手大小的影响。实测参考：张开手 d≈0.5~1.6，捏合 d≈0.08~0.17。

> 手掌尺度曾出现「锁死」缺陷：若历史值恰好是塌陷的小值（手侧转/握拳时掌宽可塌到 51px），此后的真实值会被永久判为「突变」而拒绝更新，归一化距离被放大 3~4 倍 → 捏合提前跳出、画线不连贯。现已加「连续 8 帧不合理即重新锚定」+「掌宽/掌长取大者」双重保护。日志中 `掌宽=` 若长期停在某个异常小值，即为该现象复发。

## 五、代码结构（单文件 `Sources/HandMark/main.swift`）

- `DrawState`：线程安全的笔画/指尖/绘制**相位**（Idle / Drawing / TrackingLost）与当前笔刷（V3.0 起每笔记录起笔时的 `BrushSelection` 快照；V4.0 起追踪丢失即封存，恢复后另起一笔，绝不跨丢失区间连线）
- `OverlayWindow` + `OverlayView`：全屏透明画板，**每条笔画独立 CAShapeLayer**（颜色/粗细来自该笔的笔刷快照）+ 指尖激光光点（halo/core/hot 三层）+ `OverlayFeedbackView` 非阻挡反馈条
- `HandTracker`：AVCaptureSession + `VNDetectHumanHandPoseRequest`，输出指尖屏幕坐标、捏合判定、掌心朝向角、预览帧；V4.0 起负责「笔尖锚点 → 坐标映射 → 指针滤波 → 追踪中断判定」这条链路
- `PointerMapper` / `MappingROI` / `ROICalibrator`（`Sources/HandMarkCore/PointerMapping.swift`，纯逻辑可单测）：坐标空间变换、固定 ROI 有效性判定与四角标定聚合；`ROIStore`（main.swift）负责 roi.json 读写
- `OneEuroFilter1D/2D` / `LegacyEMAFilter2D`（`Sources/HandMarkCore/OneEuroFilter.swift`）：1€ Filter 与保留的旧 EMA，异常间隔/首帧/丢失后均重新初始化
- `SystemVolumeController`（`Sources/HandMark/SystemVolumeController.swift`）：公开 Core Audio API 读写默认输出设备音量，每次操作重新解析设备，不支持时如实报错
- `PreviewView` / `PreviewController`：预览小窗（画面 + 关键点 + 状态条 + 显隐）
- `PanelActions` + `makeControlPanel`：清除 / 隐藏预览 / 退出

```
✏️ 开始绘画，起点=(850, 775)
⏹ 停止绘画，笔画数=1
```

- 透明画板：CGWindowList 实测存在 layer=1000、1512×982 全屏窗口，鼠标事件穿透正常。
- 摄像头：30fps，预览帧数与处理帧数完全一致（254/254），证明预览复用同一路采集，无第二路摄像头。
- 手势：真实捏合距离 0.008~0.026 时触发开始绘画，松开后停止；状态随之切换。
- 预览方向：曾出现上下翻转，已用离屏渲染测试定位（翻转视图中直接 draw CGImage 会颠倒）并修正为 `translate(w, camH) + scale(-1,-1)`。
- 绘画方向：曾出现"手向上、线向下"。根因是 CAShapeLayer 使用**左下原点**坐标系，而指尖是**左上原点**的屏幕坐标，导致 y 未转换。已用离屏渲染测试验证（不翻转时 y=10 的点画到了底部），修复方案：`OverlayView.isFlipped = true` + `layer.isGeometryFlipped = true`。

## 七、排查方向类问题

- 手向上、线向下 → `main.swift` 顶部 `FLIP_Y` 改为 `true`（一处开关，屏幕轨迹与预览叠层同步生效），`./build.sh` 重建。
- 手向左、线向右 → `MIRROR_X` 改为 `false`。
- 看实时数值：`tail -f ~/Library/Logs/HandMark.log`，抬手时「指尖屏幕坐标」的 y 应变小（越靠屏幕顶部越小）。
- **捏合提前跳出 / 画线不连贯**：先看心跳里的 `掌宽=`（正常 150~250px）。若长期停在 51px 之类的异常小值 → 手掌尺度锁死，归一化距离被放大，见第四节说明。再看 `置信度=`（正常 0.5~0.9）；若长期低于 0.3，多为光线不足或手离摄像头太远，改善光照后再试，必要时把 `MIN_CONFIDENCE` 调低。
- **旋钮不触发**：看心跳里的 `旋钮[…]` 诊断段——`四指伸直n/4`、`拇伸`、`张开`、`可靠` 任意一项为 × 就是卡点（小指天生短，已按指分档阈值；若仍 × 说明手指确实没伸直或置信度不足）。已进入 `调节中` 但不切换时，看 `累计=X°`：掌心角没累计到约 30° 说明旋转幅度不够，可把 `KNOB_TRIGGER_DEGREES` 调到 20 试试。
- **音量不触发 / 提示不可用**：启动日志会打印 `✅ 系统音量可用（公开 Core Audio API），当前 xx%`；若为 `⚠️ 系统音量不可用`，说明当前默认输出设备不支持直接设置音量，此时手势只识别不改动系统，且屏幕会如实提示原因（不会假报音量已变）。拇指方向判据是「拇指末节（IP→指尖）以竖直分量为主」，手掌旋转/左右手不影响上下判定。

## 八、手势优先级

所有手势由 `GesturePriorityCoordinator`（`Sources/HandMarkCore`）统一裁决，同一帧最多执行一个动作：

```
清屏（六→握拳） > 激光（已默认关闭） > PPT 翻页 > 五指旋钮 > 拇指音量 > 捏合绘画
```

任意高优先级状态占用时，低优先级手势被挂起（捏合不落笔）；捏合一旦上手也会反向锁定，避免控制手势抢占画笔。手离开画面时所有状态机复位，不会永久锁定。

## 九、V4.0 全屏可达性与精细绘制

### 9.1 优化前的基线（实测，来自 `~/Library/Logs/HandMark.log` 中 V4.0 首次启动之前的 887 条「手部=已识别」心跳）

| 指标 | 数值 | 含义 |
|---|---|---|
| 指尖实际覆盖 | X 10.3%~94.4%、Y 13.4%~100.1% | 左侧约 10% 宽、右侧约 6% 宽、顶部约 13% 高的边条够不到 |
| 舒适区（p5~p95） | X 仅占屏宽 **30.3%**、Y 占 **69.8%** | 水平方向尤其憋屈 |
| 外圈 8% 边距样本占比 | **8.8%** | 边缘不是"能到"，是勉强够到且停不住 |
| 相邻心跳(1s)位移 p10 | **9.0 px** | 手静止时的残余漂移（1Hz 采样代理值） |
| 掌宽测量变异系数 | **31.3%**（28~307px） | 手部尺度本身很不稳定，不宜直接当映射增益 |

> 这些是**优化前**的数据，不是优化后的结果。覆盖率统计的是"手实际停留过的位置"，不等于物理可达范围；要证明"够不到边缘"必须做有目的的九宫格实测。

### 9.2 做了什么

1. **固定 ROI 活动区域映射**（`PointerMapping.swift`）：校准四角 → ROI 内的手部坐标放大到全屏，越界一律**钳制**（不做无界外推）。未校准 / ROI 失效（跨度 <15%、边界颠倒、越出画面）/ 镜像方向变化 → 自动回退 Legacy，并在启动日志里写明原因。
2. **1€ Filter**（`OneEuroFilter.swift`）：速度自适应低通，替代固定 EMA。首帧、异常帧间隔（>0.25s）、手部丢失恢复均重新初始化，不会跨丢失区间连成长线。指针（红色光点）与落笔**共用同一份**滤波结果，不二次平滑。
3. **绘制状态机显式化**：`DrawState` 提供 Idle / Drawing / TrackingLost 三相；追踪中断 ≥120ms 即封存当前笔画，恢复后必须重新起笔，绝不把两段笔迹连成一条线（单测 `DrawStateTrackingTests` 锁死该行为）。
4. **可复现测量**：每积累 1 秒做一次逐帧评估，若**原始**坐标包围盒 <30px 判定为"手静止"，此时滤波后坐标的包围盒即为**静止漂移**，日志行 `⏸ 静止窗口 …`，同时记录掌宽变化用于阶段 4 评估。

### 9.3 可复现的测量方式

```bash
python3 tools/analyze_log.py --list              # 列出所有启动分段
python3 tools/analyze_log.py --startup 0         # 分析最近一次启动之后
python3 tools/analyze_log.py --startup 1         # 分析倒数第二次启动（用于新旧 A/B）
python3 tools/analyze_log.py --all               # 聚合全部日志
python3 tools/analyze_log.py --startup 0 --json  # JSON 输出，便于做对比表
```

输出包含：实验配置（映射模式 / 滤波模式 / 增益 / ROI 边界）、指尖覆盖、逐帧抖动与静止漂移、掌宽稳定性、追踪事件计数。心跳里同步输出 `映射= 增益= 滤波= 追踪= 帧抖动[原始→滤波] 静止窗口= 平均漂移= 丢失= 封存= 重锚=`，可直接肉眼比对。

### 9.4 建议的实测顺序（需真实摄像头，本机尚未完成）

1. **校准**：菜单栏 ✋ →「校准活动区域（4 步）」，确认日志出现 `🎯 校准完成` 与 `🗺 已加载 ROI[…]`，心跳 `映射=ROI 增益=` 由 `1512x982` 变为更大的值。
2. **九宫格**：依次指向屏幕九个目标点，记录日志中 `指尖屏幕坐标` 与目标点的像素误差。
3. **四角四边**：确认在舒适范围内即可指到四角（这是 ROI 的核心验收）。
4. **静止悬停**：手停住 3 秒不动，看是否出现 `⏸ 静止窗口`，记录 `滤波后漂移`。
5. **A/B**：把 `POINTER_FILTER_MODE` 改为 `.legacyEMA` 重建，重复 2~4，与 1€ 的结果对比后再决定保留哪个。
6. **轨迹质量**：慢速直线 / 快速直线 / 圆 / 折线 / 小字，看转角是否被抹圆、末端是否丢失。

### 9.5 已知限制

- **ROI 会等比例放大噪声**：ROI 缩小到画面的一半，同样的手部抖动在屏幕上就是两倍。因此 ROI 与 1€ Filter 必须同时使用；只开 ROI 会更抖。
- **掌宽归一化（阶段 4）暂不采纳**：掌宽变异系数 31%，把它引入映射增益只会把噪声注入坐标；现有归一化坐标 + 固定 ROI 已经消除了主要增益漂移来源。需要专门的对比实验（手前后移动而指尖不动时观察坐标漂移）才能重新评估。
- **1€ 参数是调试起点**，不存在对所有摄像头/坐姿通用的最优值，必须按 9.4 的第 5 步实测后确定。
- PPT 翻页仍受**辅助功能权限**阻塞（系统设置 > 隐私与安全性 > 辅助功能勾选 HandMark 后重启）。
